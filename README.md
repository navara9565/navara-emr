# ระบบเวชระเบียนออนไลน์ · ณวรา ศูนย์ดูแลผู้สูงอายุและฟื้นฟูสมรรถภาพ

ระบบเวชระเบียนสำหรับ Nursing Home พร้อมฐานข้อมูลจริง (SQLite), sync เรียลไทม์ข้ามอุปกรณ์ (WebSocket) และระบบล็อกอินแยกบทบาท

## ความสามารถ

- 👥 รายชื่อผู้ป่วย + แจ้งเตือนสัญญาณชีพผิดปกติ (จุดแดงเต้น คลิกกรองรายชื่อได้)
- 🗺️ ผังเตียงตามชั้น/ห้องจริง (ชั้น 1–3, N101–N304) เพิ่ม/ลดเตียงต่อห้องได้
- 🛎️ รับผู้ป่วยใหม่พร้อมเลือกเตียง · 🔀 ย้ายเตียง · 📤 จำหน่ายผู้ป่วยเข้าเวชระเบียนกลาง (อ่านอย่างเดียว)
- 📋 เวชระเบียน 8 หมวด: ข้อมูลทั่วไป / ประวัติ–ตรวจร่างกาย / Vital Signs / ยา (พร้อมประวัติปรับยา) / Nurse Note / Doctor Note / PT-OT Note / การประเมินอื่นๆ (ADL Barthel + Fall risk Morse — เลือกวันประเมิน ประเมินซ้ำได้ คิดคะแนน/แปลผลอัตโนมัติ)
- 📷 QR ปลายเตียง: พยาบาลสแกนด้วยมือถือ → ลง Vital Signs ตามรอบเวลา → ขึ้นจอทุกเครื่องทันที
- 🖨️ พิมพ์สรุปเป็น PDF ต่อหมวด + พิมพ์การ์ด QR ติดปลายเตียง
- 🔐 บทบาท 7 แบบ: ผู้ดูแลระบบ / แพทย์ / พยาบาล / นักกายภาพบำบัด / นักกิจกรรมบำบัด / ผู้ดูแลผู้ป่วย / อื่นๆ (ดูอย่างเดียว)
  - นักกายภาพ-กิจกรรมบำบัด: บันทึกได้เฉพาะ PT/OT Note + Vital Signs ที่เหลือดูอย่างเดียว
  - ผู้ดูแลผู้ป่วย: บันทึกได้เฉพาะ Vital Signs (รวมสแกน QR ปลายเตียง)
  - เวชระเบียนกลางแก้ไขได้เฉพาะผู้ดูแลระบบ · สิทธิ์ถูกตรวจทั้งหน้าจอและฝั่งเซิร์ฟเวอร์

## วิธีติดตั้ง (ครั้งแรกครั้งเดียว)

ต้องมี [Node.js](https://nodejs.org) เวอร์ชัน 22 ขึ้นไป บนเครื่องที่จะใช้เป็นเซิร์ฟเวอร์ (คอมพิวเตอร์เคาน์เตอร์พยาบาลก็ได้)

```bash
npm install
npm run build
```

## วิธีเปิดใช้งาน

```bash
npm start
```

หน้าจอจะแสดง URL สองแบบ:

```
✅ EMR server running
   Local:   http://localhost:3000
   Network: http://192.168.1.50:3000   ← ใช้ URL นี้บนมือถือ (WiFi เดียวกัน)
```

- **บนคอมเครื่องนี้** → เปิด `http://localhost:3000`
- **บนมือถือ/แท็บเล็ต/คอมเครื่องอื่น** → ต่อ WiFi วงเดียวกัน แล้วเปิด URL แบบ `Network`
- **สำคัญ:** เวลาจะพิมพ์การ์ด QR ปลายเตียง ให้เปิดระบบผ่าน URL แบบ Network ก่อนพิมพ์ เพื่อให้ QR ชี้ไปที่ address ที่มือถือเข้าถึงได้

ปิดเซิร์ฟเวอร์ = กด `Ctrl+C` (ข้อมูลไม่หาย เก็บในไฟล์ฐานข้อมูล)

## บัญชีเริ่มต้น

| ชื่อผู้ใช้ | รหัสผ่าน | บทบาท | สิทธิ์ |
|---|---|---|---|
| `admin` | `admin1234` | ผู้ดูแลระบบ | ทุกอย่าง + แก้ไขเวชระเบียนกลาง + จัดการผู้ใช้ |
| `doctor1` | `doctor1234` | แพทย์ | ทุกอย่างทางคลินิก รวม Doctor Note |
| `nurse1` | `nurse1234` | พยาบาล | บันทึกทุกอย่าง ยกเว้น Doctor Note |

> 📤 **เวชระเบียนกลาง** (ผู้ป่วยที่จำหน่ายแล้ว) ทุกบทบาทเปิดดู/พิมพ์ได้ แต่**แก้ไขหรือรับกลับเข้าดูแลได้เฉพาะผู้ดูแลระบบ** — ระบบตรวจสิทธิ์ทั้งฝั่งหน้าจอและฝั่งเซิร์ฟเวอร์

> ⚠️ **เปลี่ยนรหัสผ่านทันทีหลังใช้งานจริง** — ล็อกอินเป็น admin → ปุ่ม "⚙️ ผู้ใช้งาน" → เปลี่ยนรหัสผ่าน และเพิ่มบัญชีจริงของเจ้าหน้าที่แต่ละคน

## ข้อมูลเก็บที่ไหน / สำรองข้อมูลอย่างไร

ข้อมูลทั้งหมดอยู่ในไฟล์เดียว: **`server/data/emr.db`**
(Vital Signs และบันทึกต่างๆ แยกเก็บเป็นตารางของตัวเอง — เคสอยู่นานหลายปีระบบก็ยังเร็วเท่าเดิม)

- **สำรองอัตโนมัติ:** ระบบสร้างสำเนาให้เองทุกวันใน `server/data/backups/` (เก็บรายวัน 30 ชุด + รายเดือน 12 ชุด หมุนเวียนลบเอง — ไม่มีงานให้เจ้าหน้าที่ทำ)
- **สำเนานอกเครื่อง (งานเดียวที่ต้องทำ):** ล็อกอิน admin → ⚙️ ผู้ใช้งาน → ปุ่ม **"⬇ ดาวน์โหลดข้อมูลสำรอง"** สัปดาห์ละครั้ง แล้วเก็บลง USB/Google Drive — กันกรณีเครื่องเซิร์ฟเวอร์เสียหาย
- **กู้คืน:** นำไฟล์สำรองมาวางแทน `server/data/emr.db` แล้ว start ใหม่
- **เริ่มระบบใหม่ทั้งหมด (ล้างข้อมูล):** ลบโฟลเดอร์ `server/data/` แล้ว start ใหม่ — ระบบจะสร้างข้อมูลตัวอย่าง + บัญชีเริ่มต้นให้อีกครั้ง
- **เคสอยู่ยาว:** หน้า Vital Signs เปิดมาแสดง 7 วันล่าสุด (สลับ 30 วัน / 3 เดือน / ทั้งหมดได้) พร้อมตาราง**สรุปรายเดือน** (ค่าเฉลี่ย/ต่ำ-สูง/จำนวนครั้งผิดปกติ) สำหรับรีวิวเคสระยะยาว · บันทึกต่างๆ แสดงทีละ 20 รายการ กด "ดูเพิ่ม" เพื่อโหลดย้อนหลัง

## โครงสร้างทางเทคนิค

```
server/
  index.js    ← REST API + WebSocket + เสิร์ฟหน้าเว็บ (พอร์ตเดียว)
  db.js       ← ชั้นฐานข้อมูล (ไฟล์เดียวที่ต้องแก้ ถ้าจะย้ายไป Postgres/Supabase)
  data/emr.db ← ฐานข้อมูล SQLite (สร้างอัตโนมัติ)
src/           ← หน้าเว็บ React (Vite)
```

## ใส่โลโก้ของศูนย์

วางไฟล์โลโก้ที่ **`public/logo.png`** (หรือ `public/logo.jpg`) — แอปจะแสดงโลโก้จริงที่หน้าเข้าสู่ระบบทันที
ถ้าไม่มีไฟล์ ระบบจะใช้โลโก้ต้นไม้แบบ SVG ที่วาดไว้ให้แทน (ไม่มีรูปแตก)
แนะนำ PNG พื้นโปร่งใสจะกลืนกับพื้นหลังสวยที่สุด

## การนำขึ้นอินเทอร์เน็ต (Deploy)

โปรเจกต์นี้พร้อม deploy แล้ว (มี `Dockerfile` + `render.yaml` ให้) — สรุปทางเลือก:

| ทางเลือก | ค่าใช้จ่าย | ข้อมูลถาวร | เหมาะกับ |
|---|---|---|---|
| **คอมที่ศูนย์ (LAN)** | ฟรี 100% | ✅ อยู่ในศูนย์ | ใช้จริง — ปลอดภัยข้อมูลผู้ป่วยที่สุด |
| LAN + **Tailscale** (ฟรี) | ฟรี | ✅ อยู่ในศูนย์ | เพิ่มการเข้าจากนอกศูนย์แบบปลอดภัย |
| **Render.com** (Starter + Disk) | ~$7.25/เดือน | ✅ | ออนไลน์เต็มรูปแบบ ง่ายสุด มี HTTPS ให้ |
| Render.com (Free) | ฟรี | ❌ หายเมื่อรีสตาร์ท | เดโม/ทดลองเท่านั้น |
| **Oracle Cloud** (Always Free VM) | ฟรีถาวร | ✅ | ออนไลน์ฟรีจริง แต่ต้องดูแล VM เอง |

**Deploy บน Render (แนะนำถ้าต้องการออนไลน์):**
1. อัปโหลดโค้ดขึ้น GitHub (repo ส่วนตัว)
2. สมัคร [render.com](https://render.com) → New → **Blueprint** → เลือก repo → Render อ่าน `render.yaml` และตั้งค่าให้อัตโนมัติ (region Singapore)
3. รอ build เสร็จ จะได้ URL แบบ `https://navara-emr.onrender.com` — เข้าจากมือถือ/คอมได้ทุกที่ มี HTTPS ในตัว
4. เข้าไปเปลี่ยนรหัสผ่าน admin ทันที และพิมพ์การ์ด QR ปลายเตียงใหม่จาก URL จริง

**ข้อควรระวัง (PDPA):** ถ้าขึ้นคลาวด์ = ข้อมูลผู้ป่วยอยู่นอกศูนย์ ควรใช้รหัสผ่านที่แข็งแรง เปลี่ยนรหัสเริ่มต้นทั้งหมด และพิจารณานโยบายข้อมูลส่วนบุคคลของศูนย์ก่อน

### อยากย้ายขึ้นคลาวด์ / ใช้ Postgres หรือ Supabase?

โค้ดถูกออกแบบให้ชั้นฐานข้อมูลแยกอยู่ใน `server/db.js` ไฟล์เดียว — เขียนฟังก์ชันชุดเดียวกัน (listPatients, upsertPatient, createSession, ...) ให้ชี้ไปฐานข้อมูลใหม่ ส่วนอื่นทั้งระบบไม่ต้องแก้เลย ตัวเซิร์ฟเวอร์ deploy ขึ้น VPS/คลาวด์ได้ตรงๆ (แนะนำให้ใส่ HTTPS ผ่าน reverse proxy เช่น Caddy/nginx ถ้าเปิดออกอินเทอร์เน็ต)

### หมายเหตุความปลอดภัย

ระบบนี้ออกแบบสำหรับใช้ **ในเครือข่ายภายในของศูนย์** (LAN/WiFi ส่วนตัว):
รหัสผ่านถูกเข้ารหัส (bcrypt), ทุก API ต้องล็อกอิน, สิทธิ์ถูกตรวจฝั่งเซิร์ฟเวอร์ทุกครั้ง
หากจะเปิดให้เข้าจากอินเทอร์เน็ตภายนอก ควรเพิ่ม HTTPS และปรึกษาผู้ดูแลระบบเรื่อง PDPA/ความปลอดภัยข้อมูลผู้ป่วยก่อน
